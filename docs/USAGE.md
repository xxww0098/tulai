# 使用指南

本文介绍账号设置、图片生成、下载和批量工具。安装和快速开始见[项目首页](../README.md)。

## 首次设置

第一次打开时会出现设置向导。第一步在豆包、千问、Antigravity、ChatGPT 里选一个，第一次只勾选选中的这个平台。豆包、千问和 ChatGPT 接着确认浏览器，弹出登录页，在网页中完成登录。完成后自动进入主界面，出图页停在刚设置的平台上。向导展示状态写在配置库里；之后即使没有可用账号也不会自动弹出。侧栏的「设置向导」可以手动打开，用来完成设置、再加一个平台，或给已选的平台多加一个账号。

首次使用在向导或浏览器页点击「安装 Camoufox」。应用准备固定版本 Node、Camoufox 启动库、Firefox 内核和指纹模型，无需另装 Python、Node 或系统浏览器。Windows x64 发布包内含 Node 和启动库；浏览器内核与指纹模型仍需联网下载。其他受支持架构的源码构建会按需下载启动环境和依赖；首次下载体积较大。支持 Windows x64、macOS Intel / Apple Silicon，以及 Linux x64 / ARM64。

选 Antigravity 时，第二步检查本机有没有 `agy` 命令行（依次找设置里的路径、官方脚本的默认位置、PATH）。没有就显示官方安装命令和复制按钮，另有官方下载页链接；装在别处的可以手动选文件。装好后自动识别，不用重启 tulai，「下一步」随后亮起。第三步用 Google 授权码登录，授权链接在该账号的内置 Camoufox 窗口打开；也可直接导入本机已登录的 CLI 账号。

### 账号与代理

同一个平台可以添加多个账号，任务按账号状态和可用额度调度。某个账号出现额度用尽、请求过于频繁、未登录或验证码时，tulai 会把它标成冷却或已用尽，并改用下一个还能用的账号；其它账号还在时，这一批不会整批停掉。已经点过发送、但不确定有没有送出的任务不会换号重发。登录失败要在浏览器里重新登录后，在列表里点「恢复选中」。豆包和千问默认在账号浏览器内自动加载页面桥，不需要手动安装或配对。

生图和洗图默认使用无窗口的账号浏览器，整批任务结束或停止后自动退出本批使用的浏览器，登录资料会保留。需要人工验证时，在对应账号点击「查看浏览器」，选择「接管操作」；完成后点击「恢复自动」或收起查看器，任务继续。需要独立浏览器窗口时，可先停止该账号，再从浏览器页启动。

账号可设置独立 HTTP 或 SOCKS5 代理，留空使用全局代理。HTTP 支持认证，SOCKS5 认证受 Playwright 限制而不支持。代理在下次打开账号时生效；运行中的账号不能修改。硬件身份保持稳定，Firefox 版本和代理出口派生的时区、语言、地理位置、WebRTC 地址在启动时更新。技术范围、验证方式和已知边界见 [Camoufox 接入说明](CAMOUFOX.md)。

### ChatGPT 和 Antigravity

ChatGPT 使用 Go 实现的网页图片协议，参考 [chatgpt2api](https://github.com/basketikun/chatgpt2api)，无需安装 Python 或单独运行后端。选择「ChatGPT」后添加账号，在该账号的 Camoufox 窗口登录。支持文生图、单图洗图和模型选择；「设置 → 账号与并发」可选 `gpt-image-2` 或 `auto`。网页会话凭据仅在内存中使用，登录资料仍由账号浏览器保存。额度用尽、限流或登录失效时使用现有账号调度；确认提交后，结果获取失败只查询原对话，不换号重发。未确认的提交需先检查网页；退出应用后不保留该恢复状态。需要 Turnstile 或 Arkose 验证时转人工处理。当前未提供 Codex 生图链路、账号密码批量导入或对外兼容 API 服务。

Antigravity 生图、洗图和额度查询使用 `agy` CLI。每个账号在账号目录保存独立的 OAuth 凭据（权限 `0600`）；执行前切换系统凭据及该账号的 CLI 文件回退凭据，执行后保存刷新后的 OAuth。出图、额度查询、导入和登录共用切号锁，登录取消或失败会恢复原凭据。凭据格式与系统存储键参考 [cockpit-tools](https://github.com/jlcodes99/cockpit-tools/blob/main/src-tauri/src/modules/antigravity_credential.rs)：macOS 为 `gemini` / `antigravity` 钥匙串项，Windows 为 `gemini:antigravity`，Linux 使用 Secret Service（需安装 `secret-tool`）。独立 HOME 用来分开日志和生成结果，账号身份通过切换 OAuth 确定。系统凭据与本机其它 Antigravity 客户端共用，运行 tulai 任务时应避免在其它客户端同时切号。

账号表显示 Gemini 模型的 **5小时 / 7天已用百分比**，悬停可看重置时间。每次成功读取都会保存到本地配置库，重启后仍可查看。批次首单派发前会等待读额完成；之后任务结束会触发刷新，空闲时每 5 分钟刷新。调度按两个窗口中较低的剩余比例从高到低选账号；任一窗口用尽或 CLI 返回额度不足，会自动切到下一个可用账号。读到 Gemini 额度时，以额度优先顺序替代按固定任务数轮号；未知或已过期的记录不会优先于已确认有额度的账号。全部用尽时保留待处理任务，等对应窗口重置。

## 图片生成

第一次打开先完成设置向导。在「图片生成」页面选择「自由生图」「批量洗图」或「裂变图片」；三种模式各自保留草稿和历史。顶部选择服务商，左侧准备输入并开始，右侧查看该服务商的账号和结果。

「裂变图片」选择一张母图，默认指令要求保留可识别主体，并以四种构图、视角和配色分别生成一张图；可编辑共用指令，四种方向及母图约束仍会附加。每次使用当前选中的一个服务商，固定等待结果，最多保存每个方向的一张图到 `<目录>/裂变图片/<YYYY-MM-DD>/<母图文件名>_01.ext`；开启生图自动编号时也适用于裂变图片。完成后用 63 位 pHash 比较各结果的低频视觉结构，两两相似度超过 60% 的结果标记为「需核对」，可点击「重新生成」；重试会保留其他方向的结果和原有图片文件。更换母图时，已有的裂变任务会收进历史。pHash 是结构相似度的近似，不能证明语义相似度或主体确实源于母图，请结合图片人工确认。服务商未返回图片、检测失败或结果过于相似时，不能保证一次得到四张通过检查的图。

1. 在顶部选择豆包、千问、ChatGPT 或 Antigravity。每次开始只向选中的服务商发送任务；启动按钮上方也会显示本次发送目标。
2. 自由生图时直接填写提示词，每行一条。从文本文件载入时，空行隔开的段落会合并为一条；已保存的提示词模板则整段发送。参考图可选：不添加时按提示词生图，添加后按图片生成，提示词按顺序循环。选择豆包时，可在三种模式的开始区域选择常用或自定义输出比例、像素；设置会保留，保存时按目标尺寸缩放补白或裁剪。比例折算后命中豆包「比例」菜单的原生选项（1:1、2:3、3:4、4:3、3:2、9:16、16:9）时，任务直接在网页上选择原生比例，画面原生出图；原生菜单不可用或比例不在菜单里（如 4:5）时，仍按提示词说明加后期缩放处理。
3. 批量洗图时添加原图或选择文件夹，再使用默认洗图指令或修改指令。「豆包洗图」模板会尝试提取商品主图并还原为平面图案。开始区域的「风格」可选择保持原风格、像素、水彩、油画、动漫、扁平插画、国风水墨、黑白线稿或复古版画；选择会保留到下次使用。保持原风格不会额外添加要求；选择其他风格时，预设风格优先于原指令和「组合参数」中的风格，其他组合参数仍生效。自定义风格可选「保持原风格」后在「组合参数」中填写。风格只影响新建的洗图任务，重试保留原任务的指令。每张原图单独处理，结果按原文件名保存。两种模式都可以从下拉框选择提示词；在「提示词」页按生图、洗图或通用类型维护模板，工作区内的修改不会改变模板。原有未分类模板保留为通用。洗图页会在原图缩略图上标记「已洗」或「未洗」，并随当前任务会话保存进度。重新打开软件或恢复历史任务后，已成功保存结果的原图不会再发送；点「继续洗图」只会处理剩余未洗原图。失败、停止或中断的图片仍算未洗，可在下次继续时重试。原图图库中的「清除已洗」可移除已洗条目，保留未洗条目、原文件和洗图结果。
4. 第一次使用按设置向导登录。要再加账号，可以在当前服务商的账号区添加，或打开设置向导。
5. 点 **开始出图**、**开始洗图** 或 **开始裂变**。任务会使用所选服务商的可用账号，发送输入、等待结果并保存。运行中切换服务商只改变当前查看的账号和结果，不会更改正在运行的任务。输出目录可在设置中查看和修改。

并发、重试、等待和「去水印（实验）」在设置页。不改也能开跑。关闭并发时一次运行一批任务；开启时按可用账号自动安排，设置会在下一批任务生效。豆包页面桥洗图每批最多将 10 张源图放入同一条消息；有两个空闲账号且待处理图片使用相同提示词时，会适当分批，让两个账号同时工作。结果根据豆包返回的源图关联保存；无法确认对应关系时放入「待核对」。

结果都写进设置里的那一个输出目录。生图是 `<目录>/生图/<YYYY-MM-DD>/<提示词>_01.ext`，洗图是 `<目录>/洗图/<YYYY-MM-DD>/<原文件名>_01.png`。日期按保存时的本地日历，同一天的各次运行进同一个文件夹。一条回复里的多张图从 `_01` 接着编；文件已经存在就继续 `_03`、`_04`，不覆盖。提示词文件名取第一行，去掉 `\ / : * ? " < > |` 和不可见字符，最长 40 个字符；收成空串时用「文生图」。提示词和源图都空时不能开始，引擎返回「任务队列为空：请添加提示词，或添加源图片」。

在设置的「输出」页可以分别给生图和洗图开启「自动编号」命名：文件按「前缀+补零序号」保存（如 `图001.png`），不再使用提示词或原文件名。前缀留空时只存序号（`001.png`）；可以设置编号起始值和补零位数。同一个日期文件夹里同前缀的序号接着排；起始值只在当天还没有更大的号时生效，同样不覆盖已有文件。前缀里的路径非法字符会替换成 `_`。批量洗图无法确认对应关系的「待核对」结果仍按「批次N_未匹配」保存，不受此设置影响。

重试按阶段处理：确认发送成功后，等待或保存失败只继续获取原任务结果，不重新上传、标记或发送；已保存的部分图片保留且不重复落盘。发送动作已尝试但无法确认平台是否接受时，停止当前任务并显示错误，请先检查网页再决定是否重试。历史任务不保留完整提交上下文，恢复后需先核对，再主动选择是否重新生成。

调度优先分派空闲浏览器，同一个 Camoufox 账号内串行。「发送间隔」在同一实例的连续任务之间生效，冷却不会占用其他浏览器的并发名额，最后一项完成后不再等待。停止任务会取消本地执行、重试和间隔等待，并保留已保存结果；平台已接收的远端生成无法由本地停止操作撤回。

## 网页图片下载

在「下载」页新建任务，逐行输入网页或图片地址并选择保存目录。点击「支持哪些页面？」可按网站名或页面类型查看采集范围。扫描深度为 1 时只检查当前网页；大于 1 时继续扫描同源链接。网页图片会按页面标题保存到独立目录，重复地址只下载一次；任务支持暂停、继续和失败重试。扫描最多处理 100 个网页，每页最多 8 MiB；达到上限或部分页面失败时会提示，已保存的图片保留。设置页可选最小和最大文件大小、图片宽度和高度；0 表示不限，筛选条件随任务保存。

网页和表格任务会检查下载内容的实际图片格式；如果图床返回的格式与网址扩展名不同，保存名会使用实际格式的扩展名，且不会覆盖已有文件。有标题的相册或作品分别保存。

新建任务时也可以导入 CSV 或 XLSX，选择工作表、图片网址列与文件名列，预览前 5 行并按图片列建立子目录。每个单元格按一个网址处理；公式使用表格中保存的结果，不会执行公式。暂不支持旧版 XLS、加密工作簿和隐藏在单元格中的超链接；整个工作簿会先解析，包含不支持的单元格时会提示错误。文件最多 16 MiB，表格导入最多创建 10000 条任务。

在「浏览器」页选择「网页图片下载专用环境」，或在新建下载任务时勾选「使用浏览器登录并抓取动态页面」。「支持哪些页面？」中可直接打开站点主页或图片搜索入口。专用浏览器会自动加载下载助手：网页出现可下载的图片后，点击页面右下角「下载到 tulai」，当前页就会加入下载队列；也可以复制网址回到新建任务中打开。专用环境使用 Camoufox 指纹引擎，独立保存指纹和登录资料，不参与生图账号任务。浏览器模式采集当前页，跨源图片请求不携带源站 Cookie，分区 Cookie 也不用于下载；暂不支持代理，设置全局或系统代理时需先关闭。关闭软件后继续任务前，需要重新打开相同网址的下载浏览器。

### 支持的页面

应用内「支持哪些页面？」可以按网站名或页面类型查询。以下列出采集范围和部分验证限制：

- 当前支持静态 HTML、浏览器渲染页面、商品 JSON-LD、百度、Bing、搜狗及 360 图片搜索结果页、百度贴吧帖子、B 站图文及空间相册、图虫作品及作者列表、堆糖单图及专辑、Tumblr 帖子、Imgur 帖子和相册、Pixiv 作品及作者列表、Flickr 单图及相册、Rajče 相册、豆瓣单图及相册，以及 X 图片原图地址转换。
- 新浪博客文章可读取正文图片，作者目录可分页采集文章；中关村在线产品图集和汽车之家部分车系单图可按图集采集。
- 微博帖子、图片墙和相册，微商相册单品与基础店铺，花瓣单图和画板，ArtStation 及 Behance 作品和作者主页，又拍、500px 相册、Pinterest Pin 与画板、DeviantArt 和站酷作品、Instagram 帖子、知乎文章及回答、百度百家号与今日头条文章、Unsplash 单图及搜索、IMDb 影片图片和微信公众号文章会尝试读取对应数据。
- 1688 公开店铺相册可按详情页逐张读取图片；京东、当当、唯品会、亚马逊、速卖通、拼多多、Lazada、有赞、微店、网易严选、百度爱采购、敦煌网、Alibaba 国际站、1688、淘宝和天猫商品页会尝试提取主图、规格图和详情图，Ozon 尝试读取图库和规格图，中国制造网和抖音商品会尝试读取图库和详情，JJ's House 尝试读取当前选中颜色，日本雅虎商城和 eBay 会读取当前图库及详情区，Shopee 和 Etsy 会尝试读取商品图库。
- 小红书可在浏览器模式下尝试读取笔记及主页已加载的部分笔记；QQ 空间相册列表及 QQ 群相册也需使用浏览器模式。
- yande.re 与 Gelbooru 可采集单图与搜索结果；Pexels 尝试读取单图；携程尝试读取景点相册，房天下尝试读取新房楼盘相册，CNU 尝试读取单个作品，谷德及 ArchDaily 尝试读取文章和分类列表，Houzz 尝试读取项目展示图，1x 尝试读取作品及图库展示图，WikiArt 尝试读取作者作品，快手及抖音尝试读取图文作品；Spoonflower 尝试读取公开设计和店铺当前页；苏宁易购、义乌购、得物、闲鱼、网商园、蘑菇街、兰亭、TEMU 和 SHEIN 尝试读取商品图片。
- Photoplus、拍立享与 Issuu 尝试在浏览器模式下采集可公开获取的图片。
- CNU 当前 HTTPS 站点连接有证书或握手问题，HTTP 图片是站点处理后的展示图；网商园和蘑菇街当前公开商品页可能只返回空壳。
- Spoonflower 店铺分页尚未完整支持，且在某些 fake-IP 网络中浏览器模式的跨域安全检查可能阻止请求。
- 35photo、ImgSrc、Fur Affinity、时光网、大众点评、X 单帖和作者主页、TikTok 图文及 Wellco 商品可尝试读取已识别的作品或相册；TikTok 作者主页需在下载浏览器中加载。
- ASMHentai、HentaiFox 支持已验证的作品分页，IMHentai 仅验证历史页面，E-Hentai 目前仅经过合成测试。
- Google 图片只尝试读取历史结果结构，实时搜索尚未验证。
- 昵图和汇图使用页面提供的预览图。
- 太平洋摄影部落使用页面展示图，洋码头、小米有品和政采云需在下载浏览器中加载商品。
- 国美、四座网及穷游目前只验证了历史页面，Anime-Pictures 只完成了合成测试；各站的具体限制和实测结果见下方 IDA 对照记录。

### 搜索结果和采集限制

亚马逊和 eBay 搜索结果可按商品分组下载列表主图，并尝试跟随下一页。Temu 搜索需使用下载浏览器：可手动滚动后下载已加载的商品图，也可在网页助手中自动加载，随时停止并下载。相同搜索再次下载时保留已有文件。分页、访问验证和各站实测情况见 [各大平台采集对照记录](platform-collector.md)。

当系统将 Temu 图片域名解析为 198.18.0.0/15 假 IP 时，浏览器下载会通过 Cloudflare 加密 DNS 查询这两个固定图片域名，并只连接校验过的公网地址。

部分商品采集会保留主图、规格图和详情图的分类信息，但下载目录目前不会按这些分类自动分文件夹。

贴吧、微博、微商相册、花瓣、ArtStation、Behance、Instagram、微信公众号、亚马逊、eBay、速卖通、拼多多、1688 商品页以及淘宝和天猫可能要求登录或安全验证；微博移动端帖子需要使用电脑版地址。小红书图片地址可能是压缩版本。豆瓣和 Flickr 取到的图片受站点权限和图床验证限制，可能不是原图或无法下载。Pixiv 动图仅保存静态图片并提示不完整。B 站空间的部分动态类型、登录或受保护的内容尚未完整验证。

百度、Bing、搜狗、360 及 yande.re 图片搜索最多读取 100 页，1688 每店和每册分别最多读取 1000 项，B 站空间最多读取 1000 条动态；Pixiv 作者最多读取 1000 个作品及 10000 张图片，Flickr 相册最多读取 100 页，豆瓣相册最多读取 500 页及 10000 张图片；新浪博客作者目录最多读取 100 页、1000 篇文章和 10000 张图片，小红书主页最多读取 8 屏、50 篇笔记，Unsplash 搜索最多读取 8 屏、50 张图片，通用渲染页面最多检查 8 屏。宽高筛选无法读取 AVIF、HEIC、SVG 和 ICO 的尺寸，遇到这些格式会提示失败。部分网站需要专用接口或登录态，尚未覆盖 AllPicDownloader 的全部站点。[IDA 站点注册清单与证据](allpicdownloader-ida.md)记录了本次分析范围。

## 图片去重

左栏第二个图标是「去重」。三步就够：拖图 → 选力度 → 开始。这一页与生图、洗图各自一份状态，互不干扰，也不占浏览器和引擎。

1. **拖图**：把图片或**整个文件夹**拖到页面任意位置（也可以点空白框、点「添加图片」「选文件夹」）。同一张图重复拖入只收一次，解不开的文件直接跳过。文件夹只取这一层，不进子文件夹。
2. **选力度**：严格 / 标准 / 宽松三档，默认标准。
   - 严格：只去几乎一样的图，同一张图重存、缩放、换了编码；
   - 标准：再加上轻微裁剪；
   - 宽松：轻微改色、加了角标、同款不同图也可能并到一组。
3. **开始去重**。输出默认是 `<设置里的输出目录>/去重/<YYYY-MM-DD>/`，也可以在「存到」那一行点「改」单指一个文件夹。跑完出现「结果」卡，点「打开文件夹」直达。

每组里分辨率最大的那张会被**复制**过去，原文件不动、不会被删；重复的图不复制，只写进 `重复报告.csv`（组号、保留、重复、差异位数）。重名时加 `_2`、`_3`，不覆盖已有文件。力度、输出目录和「更多设置」里的开关都存进配置库，重启还在。

判重口径都不看文件名和元数据：解码后像素摘要相同就是同一张；否则按 pHash（32×32 灰度做 DCT，取低频 63 位）的差异位数判近似。两张都没有纹理（纯色、纯白底、纯黑底）时默认还要求平均色接近，避免纯白底主图和纯黑底主图被判成同一张；要放宽这一条，在「更多设置」里勾上「纯色底也算重复」。分组用并查集，A 像 B、B 像 C 时三张同组。两两比较是 O(n²)，一万张约五千万次异或，仍在几十毫秒量级。

## 批量重命名

左侧「批量重命名」页面参考 uTools 官方插件 2.2.1 的布局。可以拖入或粘贴文件和文件夹，也可以用底栏按钮添加；「读取文件夹内容」会递归加入其中的文件，直接添加的文件夹则作为一项改名。文件可以按名称、大小或时间排序，也可以拖动调整顺序。

页面支持多条查找替换、插入文本或文件信息、自动编号、手动编辑，以及通过模型生成名称建议。手动编辑时可把多行名称粘贴到某一行，依次填入后续项目；底栏复制按钮可提取原名。编号支持阿拉伯数字、中文数字和英文字母。文件信息包括创建时间、修改时间、字节数、图片宽高和照片拍摄时间；拍摄时间目前读取 JPEG 的 EXIF。

执行前会显示新名称并检查冲突。目标已存在时不会覆盖；批内交换名称会先放到同目录的临时文件夹。执行中失败时会尝试恢复，若恢复受阻，错误信息会给出需要手动恢复的临时路径。程序意外中断时，可在源文件夹中显示隐藏文件，查找 `.tulai-rename-*` 并阅读其中的恢复说明；暂存文件保留原名。成功后可撤销本次操作；撤销时如果文件已被替换会停止。撤销记录只保存在当前运行中，添加或移除文件后清除。

普通规则默认保留扩展名的原有大小写；查找替换可勾选扩展名。查找框的模板可按位置或指定字符选取内容；手写正则用 `/表达式/g` 格式，采用 Go 正则语法，不支持 JavaScript 的后行断言等特性。智能重命名使用设置中的自定义视觉模型 API 地址、Key 和模型名，只发送文件名及用户输入的要求；它不提供原插件的文件元数据或视频信息工具调用。

## 去水印

豆包生成图自动优先下载响应中对应的 `image_ori_raw` 原图；取不到时使用页面图片，并在保存前尝试修复已校准的角落水印。处理成功时结果目录直接保存去水印图。未匹配或处理失败时保留下载图，不会重新生成。扩展的跨域下载兜底可能在浏览器下载目录留下源文件。

千问可在设置页勾选「去水印（实验）」，默认关闭。软件先保存网页下载的原图，再将匹配到的修复结果另存为 `提示词_01_去水印.png`；原图始终保留，队列每张生成图只显示一个最终结果。

扩展下载不看这个开关。`browserBackend=extension` 的豆包任务也会优先取响应中的无水印原图；回退到页面地址时先尝试去掉 `watermark` / `wm=` 查询，并对下载结果做局部修复。千问扩展下载同样会尝试局部修复。细节见 [`extension/README.md`](../extension/README.md)。

当前适配 2026-10-22 校准的豆包、千问**正方形网页导出图**，包括千问左上角「AI生成」与右下角标记。通过归一化相关匹配固定字形，再按字形蒙版估算背景并补偿邻近细纹理。没有完整背景的真实值，复杂纹理、线条或主体上的水印可能留下痕迹，不能保证无损还原；平台改变样式后可能不再匹配。非方图、16 位高精度图、动画和超出处理大小限制的图片保留原样。

算法使用纯 Go 在本机运行，不额外上传图片，也不需要 Python、OpenCV、模型权重或新的 API Key。豆包原图提取参考了 [DoubaoRemoveMark](https://github.com/xiaoyu9308/DoubaoRemoveMark) 对 `image_ori_raw` 的使用；局部修复参考了 [LSJ Watermark Remover](https://github.com/RusianHu/lsj-watermark-remover/tree/9a2f5c0f4d64edaad704fdabfdc3264c5a2b999c) 的固定模板思路，以及 [remove-ai-watermarks](https://github.com/wiltodelta/remove-ai-watermarks/tree/b5021b0f6872b533f009a2cc50af9726f33e2177) 的定位、蒙版、局部修复流程。模板来源见 [`internal/images/watermarks/README.md`](../internal/images/watermarks/README.md)。

## 本地数据与迁移

macOS 打包版和源码版将配置库、`BrowserData/` 和默认输出保存到 `~/Library/Application Support/tulai/`；Windows 保存在 `%APPDATA%\tulai\`。Linux 普通可执行程序使用启动时的工作目录。输出目录可以在设置中更改。

旧账号首次迁移会保留 ID、名称和原有 Chromium 目录，把新资料指向 `BrowserData/Camoufox/account-*`，并要求重新登录。旧路径记在配置库的 `legacy_user_data_dir`。迁移只执行一次，不复制 Chromium Cookie 到 Firefox，不删除旧资料。新账号使用随机目录标识，重命名和同名账号不会共用资料。每个目录保存 `.tulai-identity.json`；不要复制它到其他账号。

macOS 上若旧版账号资料仍在项目目录，请在首次启动新版前退出 tulai 和其内置浏览器，然后在项目目录运行 `python3 scripts/migrate_macos_data.py`。迁移会复制并校验数据库、浏览器资料及旧默认输出目录，保留原项目资料作为备份；若应用目录已有其他独立数据则停止，不会覆盖。自定义输出目录和其他历史源文件保留原路径。

配置库位于数据目录下的 `database/config.db`。已有配置使用旧目录名时，请先退出应用，再将 `数据库/` 重命名为 `database/`。

## 追查任务

每次开跑会生成一个 `run_id`。界面「运行日志」里的中文句子可以点「打开日志文件」，文件在数据目录的 `logs/` 下按天切片（`tulai.YYYYMMDD.log`），保留最近 7 天，过期自动清理。同一条也打到 stderr。

每一行按「时间、级别、模块、事件、详情」排开，空字段自动省略，不再刷出 `task_id=0`、`port=0`、`error=""`。方括号里是平台/账号、端口和阶段（`stage`），行尾保留 `task_id` 和 `run_id` 供检索；`task_id` 就是队列序号（日志里的 `#3`）。`stage` 是 `queue`、`assign`、`open`、`upload`、`submit`、`wait`、`detect_done`、`extract`、`download`、`save`、`probe`、`login` 之一，普通界面日志不显示默认的 `log` 阶段。

```text
2026-11-13 16:40:12.345  成功  [千问/千问1:9338 · submit]  #3 发送完成  (1.234s · 4 张 · 10.0 KiB)  task_id=3 run_id=20261113T164000
```

进入数据目录后，只看第 3 条（当天的切片）：

```bash
grep 'task_id=3' logs/tulai.$(date +%Y%m%d).log
```

同一批再加 run_id：

```bash
grep 'run_id=20261029T160900' logs/tulai.*.log | grep 'task_id=3'
```
