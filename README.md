# tulai

tulai 是豆包和千问的批量生图桌面应用。命令和安装包里的可执行文件也叫 `tulai`。源码仓库是 [xxww0098/tulai](https://github.com/xxww0098/tulai)。窗口标题和标题栏大字是「tulai」；macOS 菜单里的应用名也是「tulai」。支持文生图和图生图：写提示词即可开跑，也可以按源图批量改图。界面使用 [mygo](https://github.com/egoist/mygo) 原生控件，语言是 Go，目标平台是 macOS、Windows 和 Linux，纯 Go、无 CGO。

本地运行，没有授权激活，也不接远端数据库。已安装的桌面端可以从 GitHub Releases 检查并安装更新。

## 模块

| 包 | 作用 |
|---|---|
| `internal/cdp` | 保留原页面接口，实际由 Camoufox / Playwright Firefox 完成上传、截图、输入与页面桥；包名不代表仍在使用 CDP |
| `internal/camoufox` | 固定版本启动库与 Node 的安装、私有管道通信、账号指纹保存和 Firefox 页面控制 |
| `internal/browser` | 只管理 Camoufox：每账号独立进程、资料目录和代理，串行启动同一账号，正常关闭时保存登录资料 |
| `internal/strategy` | 在 Camoufox 页面操作编辑器并截获结果；扩展模式另走页面桥 |
| `internal/captcha` | 三后端：free（纯 Go CV）/ custom（视觉大模型）/ ikunocr（接码） |
| `internal/tasks` | 顺序循环、并发、重试、定时切浏览器、SHA256 去重、按日期保存 |
| `internal/dedup` | 图片去重：解码后像素 SHA-256 判完全相同，pHash（32×32 灰度 DCT 低频 63 位）判近似，并查集分组，留下分辨率最大的一张复制到新文件夹，另写一份 CSV 报告。界面只露严格/标准/宽松三档 |
| `internal/rename` | 纯 Go 批量重命名：名称预览、冲突检查、交换名称和撤销 |
| `internal/store` | SQLite `database/config.db`（`browsers` / `settings` / `prompts`）。已有同结构的库可以直接打开 |
| `internal/logging` | Info/Success/Warning/Error/Debug 环形日志 |
| `internal/ui` | mygo 原生窗口：首次设置向导、工作台、任务设置、浏览器、验证码、源图缩略图、队列表格、日志 |
| `internal/update` | 启动时和每 6 小时静默检查、横幅一键更新、GitHub 镜像回退、`tulai update`。走公开 GitHub API，不需要 token。页面桥扩展不跟着桌面端更新 |

## 运行

```bash
./dev.sh          # 开发运行（等价 CGO_ENABLED=0 go run ./cmd/tulai）
./build.sh        # 打包（go tool mygo build）
go test ./...     # 单元测试（CV 求解器 / 配置库）
go run ./cmd/tulai-camoufox-smoke   # 安装 Camoufox 并验证页面桥、输入和截图
go run ./cmd/tulai-ext-smoke   # 扩展桥冒烟：本机 WebSocket，等待千问和豆包扩展 hello
```

`go.mod` 把 MyGo 工具固定在 **v0.7.4**（`github.com/egoist/mygo`）。产品版本仍是 `mygo.json` 的 `version`，不跟着 MyGo 的版本走。

桌面端产品版本是 **0.1.9**。三个系统的安装包由 GitHub Actions 在标签 `v0.1.9` 上发布，页面桥扩展是 **0.3.13**。步骤见下文「发布 0.1.9」和 [`docs/RELEASING.md`](docs/RELEASING.md)。

已安装的桌面端会在启动时和大约每 6 小时静默检查更新（设置里的「自动检查更新」默认开着）。有新版本时顶部出现「发现新版本 x.y.z」，可以「立即更新」「稍后」或「跳过此版本」。正在进行的任务结束后才安装。也可以用菜单 **帮助 → 检查更新…**、左侧导航、设置页、设置向导，或终端里的 `tulai update`（只查看用 `tulai update --check`）。检查使用公开的 GitHub Releases，不附带 token，连接失败时尝试可配置的镜像。新发布的 macOS 应用、Windows 安装版和 Linux 用户目录版使用 MyGo 验证更新签名；免安装程序、系统包及旧版继续使用原有的 SHA256SUMS 流程。macOS 没有公证，Windows 没有代码签名。页面桥扩展单独更新。签名发布及安装方式见 [`docs/RELEASING.md`](docs/RELEASING.md)。

应用图标是仓库根目录的 `resources/icon.png`（1024×1024）。`mygo.json` 的 `icon` 指向它。`mygo build` 会把它做成 macOS `.icns`（Dock）、Windows 可执行文件图标和 NSIS 安装器图标，以及 Linux 桌面项图标。应用没有托盘菜单，因此不另做托盘图；启动时同一张 PNG 也会设到窗口（Windows / Linux）和 Dock（macOS）。

服务商账号统一使用 [Camoufox](https://github.com/daijro/camoufox)。Chrome、Edge 和内置 Chromium 的选择、探测、安装与自动加载扩展已移除。旧的手动 Chromium 扩展桥协议继续兼容。

豆包和千问默认在已绑定的 Camoufox 账号里自动加载 Firefox 页面桥，可在「设置 → 账号与并发」关闭。任务仍使用原账号的登录资料、切换顺序和额度记录，不需要手动安装或配对；批次结束后临时扩展随浏览器关闭。豆包洗图按账号最多每 10 张复用一个完成的对话，重试或对话状态变化时重新开始。响应观察和原图匹配仅处理本轮任务，原图不可用时使用页面结果及现有去水印回退。

桌面端第一次打开会生成页面桥令牌（不再把 `dev-token` 当作正式令牌），并在 `127.0.0.1:18764/tulai-pair` 上给本机扩展读取。扩展弹出页显示「已自动对接」或「需要手动配对」。自动对接失败时，仍可复制令牌手动保存。重新生成后，扩展下一轮重连会自己换上新令牌；弹出页如果选过手动保存，要点「恢复自动对接」。

Camoufox 由官方启动库通过 Playwright Firefox / Juggler 管道控制，不打开 CDP 调试端口。配置库里的旧 `port` 仅作为应用内账号标识保留，`camoufox://9333` 不是网络监听地址。

第一次打开时会出现设置向导。第一步在豆包、千问、Antigravity 里三选一，第一次只勾选选中的这个平台。豆包和千问接着确认浏览器，弹出登录页，扫码登录。完成后自动进入主界面，出图页停在刚设置的平台上。向导展示状态写在配置库里；之后即使没有可用账号也不会自动弹出。侧栏的「设置向导」可以手动打开，用来完成设置、再加一个平台，或给已选的平台多加一个账号。

选 Antigravity 时向导不启动浏览器。第二步检查本机有没有 `agy` 命令行（依次找设置里的路径、官方脚本的默认位置、PATH）。没有就显示官方安装命令和复制按钮，另有官方下载页链接；装在别处的可以手动选文件。装好后自动识别，不用重启 tulai，「下一步」随后亮起。第三步用 Google 授权码登录，或导入本机已登录的账号。

首次使用在向导或浏览器页点击「安装 Camoufox」。应用准备固定版本 Node、Camoufox 启动库、Firefox 内核和指纹模型，无需另装 Python、Node 或系统浏览器。支持 Windows x64、macOS Intel / Apple Silicon，以及 Linux x64 / ARM64。安装需要访问 Node.js、npm 和 Camoufox 上游下载服务；首次下载体积较大。

账号可设置独立 HTTP 或 SOCKS5 代理，留空使用全局代理。HTTP 支持认证，SOCKS5 认证受 Playwright 限制而不支持。代理在下次打开账号时生效；运行中的账号不能修改。硬件身份保持稳定，Firefox 版本和代理出口派生的时区、语言、地理位置、WebRTC 地址在启动时更新。技术范围、验证方式和已知边界见 [Camoufox 接入说明](docs/CAMOUFOX.md)。

同一个平台可以添加多个实例，每个实例登录一个自己的免费账号。任务按顺序分到这些账号上。某个账号出现额度用尽、请求过于频繁、未登录或验证码时，tulai 会把它标成冷却或已用尽，并改用下一个还能用的账号；其它账号还在时，这一批不会整批停掉。已经点过发送、但不确定有没有送出的任务不会换号重发。登录失败要在浏览器里重新登录后，在列表里点「恢复选中」。扩展方式不在这里启动浏览器：每个浏览器配置文件加载扩展并打开 tulai 后，会自动出现成一条扩展账号。

生图和洗图默认使用无窗口的账号浏览器，整批任务结束或停止后自动退出本批使用的浏览器，登录资料会保留。需要人工验证时，在对应账号点击「查看浏览器」，选择「接管操作」；完成后点击「恢复自动」或收起查看器，任务继续。需要独立浏览器窗口时，可先停止该账号，再从浏览器页启动。

旧账号首次迁移会保留 ID、名称和原有 Chromium 目录，把新资料指向 `BrowserData/Camoufox/account-*`，并要求重新登录。旧路径记在配置库的 `legacy_user_data_dir`。迁移只执行一次，不复制 Chromium Cookie 到 Firefox，不删除旧资料。新账号使用随机目录标识，重命名和同名账号不会共用资料。每个目录保存 `.tulai-identity.json`；不要复制它到其他账号。

macOS 打包版和源码版都将配置库、`BrowserData/` 和默认输出保存到 `~/Library/Application Support/tulai/`，不依赖项目目录。手动启动和任务执行共用同一个 profile 目录。

若旧版账号资料仍在项目目录，请在首次启动新版前退出 tulai 和其内置浏览器，然后在项目目录运行 `python3 scripts/migrate_macos_data.py`。迁移会复制并校验数据库、浏览器资料及旧默认输出目录，保留原项目资料作为备份；若应用目录已有其他独立数据则停止，不会覆盖。自定义输出目录和其他历史源文件保留原路径。

配置库位于数据目录下的 `database/config.db`。已有配置使用旧目录名时，请先退出应用，再将 `数据库/` 重命名为 `database/`。

### Windows 支持

支持 Windows 10/11，提供 amd64 与 arm64 原生 GUI 构建。运行对应架构的安装器，或直接双击 `tulai.exe`；配置库、`BrowserData/` 和默认输出均保存在 `%APPDATA%\tulai\`，不依赖启动位置，也不会写入安装目录。Windows 的开发运行同样使用该用户数据目录。

服务商网页账号需要 Windows x64 版应用和 Camoufox；当前 Camoufox 上游没有 Windows ARM64 内核。Windows ARM 设备可使用系统支持的 x64 仿真运行 x64 应用；ARM64 GUI 构建仍可用于不依赖账号浏览器的功能。

在已安装 Go 的 Windows 开发环境执行 `build-windows.cmd`，或在 macOS/Linux 交叉构建：

```sh
CGO_ENABLED=0 go tool mygo build -platform windows/amd64,windows/arm64
```

产物位于 `build/windows-amd64/` 与 `build/windows-arm64/`。安装了 NSIS 时，MyGo 会同时生成安装器；Windows 上缺少 NSIS 时，MyGo 会自动下载校验过的构建工具，macOS/Linux 缺少 NSIS 时保留独立 EXE。GitHub Actions 在 Ubuntu 上安装 NSIS 后打出同样的安装器，见 [`docs/RELEASING.md`](docs/RELEASING.md)。网页方式的要求与上文相同；Windows 真机的窗口、文件对话框和真实生成流程仍需实机验收，交叉构建通过仅证明可编译打包。

## 使用流程

第一次打开先完成设置向导。在「图片生成」页面选择「自由生图」或「批量洗图」；两种模式各自保留草稿和历史。顶部选择服务商，左侧准备输入并开始，右侧查看该服务商的账号和结果。

1. 在顶部选择豆包、千问或 Antigravity。每次开始只向选中的服务商发送任务；启动按钮上方也会显示本次发送目标。
2. 自由生图时直接填写提示词，每行一条。从文本文件载入时，空行隔开的段落会合并为一条；已保存的提示词模板则整段发送。参考图可选：不添加时按提示词生图，添加后按图片生成，提示词按顺序循环。选择豆包时，可在两种模式的开始区域选择常用或自定义输出比例、像素；设置会保留，保存时按目标尺寸缩放补白或裁剪。
3. 批量洗图时添加原图或选择文件夹，再使用默认洗图指令或修改指令。唯一的内置模板会要求保留原图主体、风格和可辨认文字，并适度重绘。每张原图单独处理，结果按原文件名保存。两种模式都可以从下拉框选择提示词；在「提示词」页按生图、洗图或通用类型维护模板，工作区内的修改不会改变模板。原有未分类模板保留为通用。
4. 第一次使用按设置向导登录。要再加账号，可以在当前服务商的账号区添加，或打开设置向导。
5. 点 **开始出图** 或 **开始洗图**。任务会使用所选服务商的可用账号，发送输入、等待结果并保存。运行中切换服务商只改变当前查看的账号和结果，不会更改正在运行的任务。输出目录可在设置中查看和修改。

### 网页图片下载

在「下载」页新建任务，逐行输入网页或图片地址并选择保存目录。点击「支持哪些页面？」可按网站名或页面类型查看采集范围。扫描深度为 1 时只检查当前网页；大于 1 时继续扫描同源链接。网页图片会按页面标题保存到独立目录，重复地址只下载一次；任务支持暂停、继续和失败重试。扫描最多处理 100 个网页，每页最多 8 MiB；达到上限或部分页面失败时会提示，已保存的图片保留。设置页可选最小和最大文件大小、图片宽度和高度；0 表示不限，筛选条件随任务保存。

网页和表格任务会检查下载内容的实际图片格式；如果图床返回的格式与网址扩展名不同，保存名会使用实际格式的扩展名，且不会覆盖已有文件。

新建任务时也可以导入 CSV 或 XLSX，选择工作表、图片网址列与文件名列，预览前 5 行并按图片列建立子目录。每个单元格按一个网址处理；公式使用表格中保存的结果，不会执行公式。暂不支持旧版 XLS、加密工作簿和隐藏在单元格中的超链接；整个工作簿会先解析，包含不支持的单元格时会提示错误。文件最多 16 MiB，表格导入最多创建 10000 条任务。

在「浏览器」页选择「网页图片下载专用环境」，或在新建下载任务时勾选「使用浏览器登录并抓取动态页面」。「支持哪些页面？」中可直接打开站点主页或图片搜索入口。专用浏览器会自动加载下载助手：网页出现可下载的图片后，点击页面右下角「下载到 tulai」，当前页就会加入下载队列；也可以复制网址回到新建任务中打开。专用环境使用 Camoufox 指纹引擎，独立保存指纹和登录资料，不参与生图账号任务。浏览器模式采集当前页，跨源图片请求不携带源站 Cookie，分区 Cookie 也不用于下载；暂不支持代理，设置全局或系统代理时需先关闭。关闭软件后继续任务前，需要重新打开相同网址的下载浏览器。

当前支持静态 HTML、浏览器渲染页面、商品 JSON-LD、百度、Bing、搜狗及 360 图片搜索结果页、百度贴吧帖子、B 站图文及空间相册、图虫作品及作者列表、堆糖单图及专辑、Tumblr 帖子、Imgur 帖子和相册、Pixiv 作品及作者列表、Flickr 单图及相册、Rajče 相册、豆瓣单图及相册，以及 X 图片原图地址转换。新浪博客文章可读取正文图片，作者目录可分页采集文章；中关村在线产品图集和汽车之家部分车系单图可按图集采集。微博帖子、图片墙和相册，微商相册单品与基础店铺，花瓣单图和画板，ArtStation 及 Behance 作品和作者主页，又拍、500px 相册、Pinterest Pin 与画板、DeviantArt 和站酷作品、Instagram 帖子、知乎文章及回答、百度百家号与今日头条文章、Unsplash 单图及搜索、IMDb 影片图片和微信公众号文章会尝试读取对应数据。1688 公开店铺相册可按详情页逐张读取图片；京东、当当、唯品会、亚马逊、速卖通、拼多多、Lazada、有赞、微店、网易严选、百度爱采购、敦煌网、Alibaba 国际站、1688、淘宝和天猫商品页会尝试提取主图、规格图和详情图，Ozon 尝试读取图库和规格图，中国制造网和抖音商品会尝试读取图库和详情，JJ's House 尝试读取当前选中颜色，日本雅虎商城和 eBay 会读取当前图库及详情区，Shopee 和 Etsy 会尝试读取商品图库。小红书可在浏览器模式下尝试读取笔记及主页已加载的部分笔记；QQ 空间相册列表及 QQ 群相册也需使用浏览器模式。有标题的相册或作品分别保存。

yande.re 与 Gelbooru 可采集单图与搜索结果；Pexels 尝试读取单图；携程尝试读取景点相册，房天下尝试读取新房楼盘相册，CNU 尝试读取单个作品，谷德及 ArchDaily 尝试读取文章和分类列表，Houzz 尝试读取项目展示图，1x 尝试读取作品及图库展示图，WikiArt 尝试读取作者作品，快手及抖音尝试读取图文作品；Spoonflower 尝试读取公开设计和店铺当前页；苏宁易购、义乌购、得物、闲鱼、网商园、蘑菇街、兰亭、TEMU 和 SHEIN 尝试读取商品图片。Photoplus、拍立享与 Issuu 尝试在浏览器模式下采集可公开获取的图片。CNU 当前 HTTPS 站点连接有证书或握手问题，HTTP 图片是站点处理后的展示图；网商园和蘑菇街当前公开商品页可能只返回空壳。Spoonflower 店铺分页尚未完整支持，且在某些 fake-IP 网络中浏览器模式的跨域安全检查可能阻止请求。

### 追查一条任务

每次开跑会生成一个 `run_id`。界面「运行日志」里的中文句子可以点「打开日志文件」，文件在数据目录的 `logs/` 下按天切片（`tulai.YYYYMMDD.log`），保留最近 7 天，过期自动清理。同一条也打到 stderr。

每一行都带这些字段：`run_id`、`task_id`、`platform`、`account`、`port`、`stage`、`elapsed_ms`、`images`、`bytes`、`error`。`task_id` 就是队列序号（日志里的 `#3`）。`stage` 是 `queue`、`assign`、`open`、`upload`、`submit`、`wait`、`detect_done`、`extract`、`download`、`save`、`probe`、`login` 之一。

只看第 3 条（当天的切片）：

```bash
grep 'task_id=3' logs/tulai.$(date +%Y%m%d).log
```

同一批再加 run_id：

```bash
grep 'run_id=20261029T160900' logs/tulai.*.log | grep 'task_id=3'
```

并发、重试、等待和「去水印（实验）」在设置页。不改也能开跑。关闭并发时一次运行一批任务；开启时按可用账号自动安排，设置会在下一批任务生效。豆包页面桥洗图每批最多将 10 张源图放入同一条消息，根据豆包返回的源图关联保存结果；无法确认对应关系时放入「待核对」。

开启自动求解时使用配置的验证码后端；需要人工验证时显示“待验证”，停止本批任务并交还网页。手动完成后可重新开始任务。

结果都写进设置里的那一个输出目录。生图是 `<目录>/生图/<YYYY-MM-DD>/<提示词>_01.ext`，洗图是 `<目录>/洗图/<YYYY-MM-DD>/<原文件名>_01.png`。日期按保存时的本地日历，同一天的各次运行进同一个文件夹。一条回复里的多张图从 `_01` 接着编；文件已经存在就继续 `_03`、`_04`，不覆盖。提示词文件名取第一行，去掉 `\ / : * ? " < > |` 和不可见字符，最长 40 个字符；收成空串时用「文生图」。提示词和源图都空时不能开始，引擎返回「任务队列为空：请添加提示词，或添加源图片」。扩展实机冒烟同样可以不设 `TULAI_EXT_IMAGE`，只设 `TULAI_EXT_PROMPT`。

重试按阶段处理：确认发送成功后，等待或保存失败只继续获取原任务结果，不重新上传、标记或发送；已保存的部分图片保留且不重复落盘。发送动作已尝试但无法确认平台是否接受时，停止整批任务并显示错误，请先检查网页再决定是否重新开始。该恢复状态仅在当前批次内有效，不跨软件重启保存。

调度优先分派空闲浏览器，同一个 Camoufox 账号内串行。「发送间隔」在同一实例的连续任务之间生效，冷却不会占用其他浏览器的并发名额，最后一项完成后不再等待。停止任务会取消本地执行、重试和间隔等待，并保留已保存结果；平台已接收的远端生成无法由本地停止操作撤回。

### 去重页（图片去重）

左栏第二个图标是「去重」。三步就够：拖图 → 选力度 → 开始。这一页与生图、洗图各自一份状态，互不干扰，也不占浏览器和引擎。

1. **拖图**：把图片或**整个文件夹**拖到页面任意位置（也可以点空白框、点「添加图片」「选文件夹」）。同一张图重复拖入只收一次，解不开的文件直接跳过。文件夹只取这一层，不进子文件夹。
2. **选力度**：严格 / 标准 / 宽松三档，默认标准。
   - 严格：只去几乎一样的图，同一张图重存、缩放、换了编码；
   - 标准：再加上轻微裁剪；
   - 宽松：轻微改色、加了角标、同款不同图也可能并到一组。
3. **开始去重**。输出默认是 `<设置里的输出目录>/去重/<YYYY-MM-DD>/`，也可以在「存到」那一行点「改」单指一个文件夹。跑完出现「结果」卡，点「打开文件夹」直达。

每组里分辨率最大的那张会被**复制**过去，原文件不动、不会被删；重复的图不复制，只写进 `重复报告.csv`（组号、保留、重复、差异位数）。重名时加 `_2`、`_3`，不覆盖已有文件。力度、输出目录和「更多设置」里的开关都存进配置库，重启还在。

判重口径都不看文件名和元数据：解码后像素摘要相同就是同一张；否则按 pHash（32×32 灰度做 DCT，取低频 63 位）的差异位数判近似。两张都没有纹理（纯色、纯白底、纯黑底）时默认还要求平均色接近，避免纯白底主图和纯黑底主图被判成同一张；要放宽这一条，在「更多设置」里勾上「纯色底也算重复」。分组用并查集，A 像 B、B 像 C 时三张同组。两两比较是 O(n²)，一万张约五千万次异或，仍在几十毫秒量级。

### 批量重命名

左侧「批量重命名」页面参考 uTools 官方插件 2.2.1 的布局。可以拖入或粘贴文件和文件夹，也可以用底栏按钮添加；「读取文件夹内容」会递归加入其中的文件，直接添加的文件夹则作为一项改名。文件可以按名称、大小或时间排序，也可以拖动调整顺序。

页面支持多条查找替换、插入文本或文件信息、自动编号、手动编辑，以及通过模型生成名称建议。手动编辑时可把多行名称粘贴到某一行，依次填入后续项目；底栏复制按钮可提取原名。编号支持阿拉伯数字、中文数字和英文字母。文件信息包括创建时间、修改时间、字节数、图片宽高和照片拍摄时间；拍摄时间目前读取 JPEG 的 EXIF。

执行前会显示新名称并检查冲突。目标已存在时不会覆盖；批内交换名称会先放到同目录的临时文件夹。执行中失败时会尝试恢复，若恢复受阻，错误信息会给出需要手动恢复的临时路径。程序意外中断时，可在源文件夹中显示隐藏文件，查找 `.tulai-rename-*` 并阅读其中的恢复说明；暂存文件保留原名。成功后可撤销本次操作；撤销时如果文件已被替换会停止。撤销记录只保存在当前运行中，添加或移除文件后清除。

普通规则默认保留扩展名的原有大小写；查找替换可勾选扩展名。查找框的模板可按位置或指定字符选取内容；手写正则用 `/表达式/g` 格式，采用 Go 正则语法，不支持 JavaScript 的后行断言等特性。智能重命名使用设置中的自定义视觉模型 API 地址、Key 和模型名，只发送文件名及用户输入的要求；它不提供原插件的文件元数据或视频信息工具调用。

### 去水印

豆包生成图自动优先下载响应中对应的 `image_ori_raw` 原图；取不到时使用页面图片，并在保存前尝试修复已校准的角落水印。处理成功时结果目录直接保存去水印图。未匹配或处理失败时保留下载图，不会重新生成。扩展的跨域下载兜底可能在浏览器下载目录留下源文件。

千问可在设置页勾选「去水印（实验）」，默认关闭。软件先保存网页下载的原图，再将匹配到的修复结果另存为 `提示词_01_去水印.png`；原图始终保留，队列每张生成图只显示一个最终结果。

扩展下载不看这个开关。`browserBackend=extension` 的豆包任务也会优先取响应中的无水印原图；回退到页面地址时先尝试去掉 `watermark` / `wm=` 查询，并对下载结果做局部修复。千问扩展下载同样会尝试局部修复。细节见 [`extension/README.md`](extension/README.md)。

当前适配 2026-10-22 校准的豆包、千问**正方形网页导出图**，包括千问左上角「AI生成」与右下角标记。通过归一化相关匹配固定字形，再按字形蒙版估算背景并补偿邻近细纹理。没有完整背景的真实值，复杂纹理、线条或主体上的水印可能留下痕迹，不能保证无损还原；平台改变样式后可能不再匹配。非方图、16 位高精度图、动画和超出处理大小限制的图片保留原样。

算法使用纯 Go 在本机运行，不额外上传图片，也不需要 Python、OpenCV、模型权重或新的 API Key。豆包原图提取参考了 [DoubaoRemoveMark](https://github.com/xiaoyu9308/DoubaoRemoveMark) 对 `image_ori_raw` 的使用；局部修复参考了 [LSJ Watermark Remover](https://github.com/RusianHu/lsj-watermark-remover/tree/9a2f5c0f4d64edaad704fdabfdc3264c5a2b999c) 的固定模板思路，以及 [remove-ai-watermarks](https://github.com/wiltodelta/remove-ai-watermarks/tree/b5021b0f6872b533f009a2cc50af9726f33e2177) 的定位、蒙版、局部修复流程。模板来源见 [`internal/images/watermarks/README.md`](internal/images/watermarks/README.md)。

### 迭代记录（测试驱动修复）

1. **桥结果未解析**：页面 `xbsCall` 曾拿到 JSON 字符串而非对象，验证码结果被一律判失败 → `base.js` 按需二次解析。
2. **JS 返回值双重编码**：`Evaluate` 对 `JSON.stringify()` 的返回给出"字符串的 JSON"，直接 Unmarshal 必失败 → 新增 `cdp.ParseJSValue` 统一双解（修复上传诊断/等待结果/抓字节/页面状态四处，"等结果永久超时"根因）。
3. **源图回声**：上传源图的预览图会被结果 hook 误收集 → 引擎预计算源图 SHA256，命中即跳过。
4. **放置区误判**：`[id*="target"]` 会命中九宫格上方的提示参考图（IMG）→ 目标区匹配排除 IMG/PICTURE 且必须在格子下方；新增按文本特征（拖/放置/放入/到这里）+ 位置的兜底扫描，替代固定 `+50px` 落点。
5. **浏览器调度与进度**：起始序号改为在队列分配时按各平台独立取模；同一浏览器的任务串行执行，不同浏览器保持并发；进度计数与队列发布增加同步保护。
6. **保存失败重试**：目录创建或写入失败时撤销结果哈希占用，恢复输出目录后可正常重试；短 RIFF/WEBP 输入不再触发越界崩溃。
7. **原生界面实测**：限定面板高度并恢复表单滚动，源图与队列采用持久的垂直分区；图片导入在主线程合并去重；文件与目录对话框从后台调用，避免阻塞 UI 动作。
8. **启动与打包**：配置库打开失败时输出明确错误并退出；macOS 打包版使用用户配置目录，手动启动与任务共用 profile 目录；补齐固定 v0.6.2 的 MyGo tool 声明，使 `go tool mygo` 与 `./build.sh` 可直接运行。
9. **工作台布局**：调整平台、提示词和保存设置的顺序，补齐空状态、任务状态与操作禁用；队列在窄窗口下优先显示状态、结果和错误，验证码密钥采用密码输入。
10. **发送与结果识别**：等待异步输入与点击结果，发送失败返回实际错误；上传预览就绪后再标记结果，排除源图预览 URL 的延迟变化，保留真正的新生成图片。
11. **Camoufox 统一账号环境**：向导与浏览器页只提供 Camoufox；配置、进程、指纹和代理按账号隔离，旧 Chromium 资料保留，首次切换需重新登录。
12. **真实输入与上传**：提示词使用浏览器可信输入；上传入口使用一次真实鼠标点击，捕获本次文件选择器的节点，避免选错旧控件。确认当前附件就绪后再发送，发送前后共用编辑器语义读值，忽略非编辑占位节点并保留真实正文。上传只触发一次 change，清理附件不会修改富文本编辑器或操作历史消息。
13. **生成候选与落盘**：无效、源图和重复候选不会立即结束任务，继续在等待窗口内取结果；流式图片链接保留签名参数。图片限制解码分配并完整解码后，按实际格式确定扩展名，以独占创建避免并发覆盖；取消会停止保存，后续写盘失败保留已保存的结果记录。结束状态区分成功、失败和未完成。
14. **旧网页升级**：软件检测旧版结果脚本后迁移到同一会话地址的干净页面，保留原页和登录状态，后续复用升级后的页面；千问的旧入口重定向后仍可复用已有页。
15. **跨域图片读取**：页面 fetch 因跨域策略失败时，通过 Firefox 独立资源页读取图片，保留登录态和完整签名参数；HTTP 403 等服务端错误仍明确返回。Camoufox 的隔离跨域页面已验证，平台实测结果以实际落盘验收为准。
16. **Ego 官方 SDK 下载流程**：上传、填写、点击、按键与文件下载交给官方 Page SDK。网页下载先写入私有临时目录，再复用 Go 校验与防覆盖保存；下载失败保留先前有效结果，损坏文件会报错，取消不会继续提交文件。软件仅回收自己已退役且确认无正文草稿的页面，防止旧测试页占满空间。
17. **网页消息与预览**：按本次提示词的新增用户消息锚定助手回复，适应旧消息重建与虚拟滚动；同一图片容器的原图和缩略表示归为一个图项。豆包二级上传菜单、千问的“上传图片”菜单、客户端推广遮挡、无标准对话框标记的图片编辑器及其“保存”入口均单独处理，下载后关闭预览供下个任务复用。千问通过官方 SDK 键盘导航到唯一图片选项后确认，目标或焦点异常即报错；存在未发送正文时保留草稿并停止上传。
18. **验证码误判与开关修复**：图片编辑器和普通画布不再仅凭 canvas 被当成验证码；识别要求局部专用标识或明确验证指令，未知类型不会默认按九宫格处理。关闭自动求解后只检测并上报阻塞，不再尝试求解、拖拽、刷新或提交；已安装页面也能更新开关。旧验证码监听按脚本版本迁移到同一地址的新文档，保留登录状态。
19. **人工验证与任务恢复提示**：发现需要人工验证时保留当前页面，不迁移或刷新验证码，不自动重试、重传或重发；同一 Ego 空间内任务串行，整批停止后显示独立的“待验证”状态与操作提示，已保存结果保留。交还浏览器的独立超时也保留“待验证”；真正取消任务仍优先停止。重新连接优先使用活跃的同平台页面。
20. **退出保存与日志布局**：正常退出时保存当前设置，已通过未失焦编辑、退出重开和配置库核对；长日志单行展示，完整详情可悬停查看，避免脚本堆栈挤满工作区。
21. **千问生成过渡态**：附件入口通过官方 SDK 聚焦并按下方向键打开菜单，再确认唯一的图片选项。生成卡的 loading 占位图保持等待，回复工具栏图标不再作为结果；只在当前助手正文图片完成加载后尝试网页下载。
22. **千问图片编辑页**：按“回到对话”、图片列表及编辑工具共同识别无 dialog 标记的编辑器，只点击侧栏外唯一的“下载”文字控件。关闭时先发送 Escape，仍未关闭时最多点击一次该编辑器明确的“关闭”按钮，再确认预览消失。
23. **可选本地去水印**：增加默认关闭且随设置保存的开关，原图完整落盘后才匹配已校准字形并另存 PNG；未匹配、处理或另存失败时保留原图并记录警告，不重发生成。覆盖取消、动画、并发防覆盖、文件名过长及真实下载样图；细纹理补偿减轻局部插值的平滑字形痕迹。
24. **按阶段重试与空闲浏览器调度**：参考 [chatgpt2api 的续轮询实现](https://github.com/basketikun/chatgpt2api/blob/dc105e51bd486bd75c8ef4f74be4bc4724bdfc33/services/image_task_service.py#L438-L508)，在现有浏览器任务边界内继续获取结果；发送状态不确定时停止，避免自动重发。修复忙碌浏览器阻塞空闲浏览器、并发绕过发送间隔，以及最后一次失败额外等待的问题。未引入新依赖。
25. **只要提示词**：源图留空时按每条提示词 × 每个平台建任务，Camoufox 和扩展都不上传。有源图时仍是图生图顺序循环。文生图结果文件名取提示词第一行。
26. **开跑步骤与图标**：主界面直接选文生图或图生图。文生图只需要提示词；图生图再添加源图。平台、打开网页和开始在同一区域。命名、调度和去水印收进默认折叠的「更多设置」。`resources/icon.png` 供窗口、Dock、Windows 安装器和 Linux 桌面项使用。
