# tulai

tulai 是豆包和千问的批量生图桌面应用。命令、仓库和安装包里的可执行文件仍叫 `xbs`。窗口标题和标题栏大字是「tulai」；macOS 菜单里的应用名也是「tulai」。支持文生图和图生图：写提示词即可开跑，也可以按源图批量改图。界面使用 [mygo](https://github.com/egoist/mygo) 原生控件，语言是 Go，目标平台是 macOS、Windows 和 Linux，纯 Go、无 CGO。

本地运行，没有授权激活，也不接远端数据库。已安装的桌面端可以从 GitHub Releases 检查并安装更新。

## 模块

| 包 | 作用 |
|---|---|
| `internal/cdp` | Chrome / Edge 的 CDP 会话、上传、下载和页面桥。包内仍保留 ego lite Page SDK，只给既有测试用，桌面任务不再调用 |
| `internal/browser` | 查找 Chrome 与 Edge、按 profile 启动、独立 CDP 端口（9333+）。Chrome 用 `BrowserData/<名称>`，Edge 用 `BrowserData/Edge/<名称>` |
| `internal/strategy` | 在 Chrome / Edge 页面操作编辑器并截获结果；扩展模式另走页面桥 |
| `internal/captcha` | 三后端：free（纯 Go CV）/ custom（视觉大模型）/ ikunocr（接码） |
| `internal/tasks` | 顺序循环、并发、重试、定时切浏览器、SHA256 去重、命名规则保存 |
| `internal/store` | SQLite `database/config.db`（`browsers` / `settings` / `prompts`）。已有同结构的库可以直接打开 |
| `internal/logging` | Info/Success/Warning/Error/Debug 环形日志 |
| `internal/ui` | mygo 原生窗口：工作台、任务设置、浏览器、验证码、源图缩略图、队列表格、日志 |
| `internal/update` | 菜单「帮助 → 检查更新…」、标题栏「检查更新」、`xbs update`。走公开 GitHub API，不需要 token。页面桥扩展不跟着桌面端更新 |

## 运行

```bash
./dev.sh          # 开发运行（等价 CGO_ENABLED=0 go run ./cmd/xbs）
./build.sh        # 打包（go tool mygo build）
go test ./...     # 单元测试（CV 求解器 / 配置库）
go run ./cmd/xbs-cdp-smoke   # Chrome CDP 连通性冒烟测试
go run ./cmd/xbs-ext-smoke   # 扩展桥冒烟：本机 WebSocket，等待千问和豆包扩展 hello
```

桌面端产品版本是 **0.1.2**。三个系统的安装包由 GitHub Actions 在标签 `v0.1.2` 上发布，页面扩展 zip 是 **0.3.6**。步骤见下文「发布 0.1.2」和 [`docs/RELEASING.md`](docs/RELEASING.md)。

已安装的桌面端可以自己更新：菜单 **帮助 → 检查更新…**，标题栏的 **检查更新**，或在终端执行 `xbs update`（只查看用 `xbs update --check`）。它请求 `https://api.github.com/repos/xxww0098/xbs/releases/latest`，不附带 token，按当前系统下载对应安装包，并用发布里的 `SHA256SUMS` 校验。这些包没有公证，也没有 Windows 代码签名。页面桥扩展不在这次更新里。`xbs version` 打印桌面端版本。

应用图标是仓库根目录的 `resources/icon.png`（1024×1024）。`mygo.json` 的 `icon` 指向它。`mygo build` 会把它做成 macOS `.icns`（Dock）、Windows 可执行文件图标和 NSIS 安装器图标，以及 Linux 桌面项图标。应用没有托盘菜单，因此不另做托盘图；启动时同一张 PNG 也会设到窗口（Windows / Linux）和 Dock（macOS）。

千问和豆包都可以改由同一个 MV3 扩展操作页面。配置库 `browserBackend=extension` 时，这两个平台走本机扩展桥，不必再添加 Chrome 或 Edge 实例。键值 `ego` 表示不走扩展，页面由网页方式里的 Chrome 或 Edge 打开。加载、实机试跑和风险见 [`docs/EXT_SPIKE.md`](docs/EXT_SPIKE.md)。

桌面端第一次打开会生成页面桥令牌（不再把 `dev-token` 当作正式令牌），并在 `127.0.0.1:18764/xbs-pair` 上给本机扩展读取。扩展弹出页显示「已自动对接」或「需要手动配对」。自动对接失败时，仍可复制令牌手动保存。重新生成后，扩展下一轮重连会自己换上新令牌；弹出页如果选过手动保存，要点「恢复自动对接」。

网页方式只有 **Chrome** 和 **Edge**，默认 Chrome。以前保存的 `ego lite` 会在打开软件时改成 Chrome。请先安装要用的浏览器，到「浏览器」页为豆包、千问添加实例，启动并登录。Chrome 的 profile 在 `BrowserData/<名称>`，Edge 在 `BrowserData/Edge/<名称>`，两套登录态不会写到一起。

同一个平台可以添加多个实例，每个实例登录一个自己的免费账号。任务按顺序分到这些账号上。某个账号出现额度用尽、请求过于频繁、未登录或验证码时，tulai 会把它标成冷却或已用尽，并改用下一个还能用的账号；其它账号还在时，这一批不会整批停掉。已经点过发送、但不确定有没有送出的任务不会换号重发。登录失败要在浏览器里重新登录后，在列表里点「恢复选中」。扩展方式不在这里启动浏览器：每个浏览器配置文件加载扩展并打开 tulai 后，会自动出现成一条扩展账号。

Windows 查找 `chrome.exe` 和 `msedge.exe`（Program Files、Program Files (x86)、LocalAppData）。macOS 查找 `/Applications` 里的 Google Chrome 和 Microsoft Edge。Linux 在 PATH、`/usr/bin` 和 `/opt/microsoft/msedge` 中查找 `google-chrome` 与 `microsoft-edge`。

macOS 打包版将配置库、`BrowserData/` 和默认输出保存到 `~/Library/Application Support/xbs/`，可直接双击启动。macOS 的 `./dev.sh` / `go run` 仍使用项目工作目录。手动启动和任务执行共用同一个 profile 目录。

配置库位于数据目录下的 `database/config.db`。已有配置使用旧目录名时，请先退出应用，再将 `数据库/` 重命名为 `database/`。

### Windows 支持

支持 Windows 10/11，提供 amd64 与 arm64 原生 GUI 构建。运行对应架构的安装器，或直接双击 `xbs.exe`；配置库、`BrowserData/` 和默认输出均保存在 `%APPDATA%\xbs\`，不依赖启动位置，也不会写入安装目录。Windows 的开发运行同样使用该用户数据目录。

安装 Google Chrome 或 Microsoft Edge，在「浏览器」页添加实例、启动并登录后再开始任务。Windows 上的可执行文件位置见上一节。

在已安装 Go 的 Windows 开发环境执行 `build-windows.cmd`，或在 macOS/Linux 交叉构建：

```sh
CGO_ENABLED=0 go tool mygo build -platform windows/amd64,windows/arm64
```

产物位于 `build/windows-amd64/` 与 `build/windows-arm64/`。安装了 NSIS 时，MyGo 会同时生成安装器；Windows 上缺少 NSIS 时，MyGo 会自动下载校验过的构建工具，macOS/Linux 缺少 NSIS 时保留独立 EXE。GitHub Actions 在 Ubuntu 上安装 NSIS 后打出同样的安装器，见 [`docs/RELEASING.md`](docs/RELEASING.md)。网页方式的要求与上文相同；Windows 真机的窗口、文件对话框和真实生成流程仍需实机验收，交叉构建通过仅证明可编译打包。

## 使用流程

启动后右侧就是开跑的地方。平台、模式、提示词、管理浏览器和开始在同一屏，不必先翻设置。

1. 选 **文生图** 或 **图生图**。新配置没有源图时默认文生图；已经导入过源图、又没手动选过模式时，打开就是图生图。选择会随设置保存。
2. 勾选豆包、千问（新配置默认豆包）。提示词在开始按钮上方，每行一条。
3. 图生图再点「添加图片」（SHA256 去重、缩略图预览）。文生图不上传源图，列表里留着的旧图也不会带上。
4. 点「管理浏览器」：选择 Chrome 或 Edge，为已勾选的平台添加实例，启动并登录。还没有对应实例时「开始任务」不可用，工作台会提示先到浏览器管理添加。
5. **开始任务**。文生图是每条提示词 × 每个平台。图生图是每张源图 × 每个平台，提示词按顺序循环。然后自动发提示词（图生图先上传）→等结果→校验→落盘。输出目录空着时，写到数据目录下的「输出结果」。

命名、前后缀、并发、重试、等待和「去水印（实验）」在左侧「任务设置 → 更多设置」，默认折叠。不改也能开跑。

开启自动求解时使用配置的验证码后端；需要人工验证时显示“待验证”，停止本批任务并交还网页。手动完成后可重新开始任务。

文生图结果在命名规则为「原文件名」时，用提示词第一行做文件名，去掉 `\ / : * ? " < > |` 和不可见字符，最长 40 个字符；收成空串时用「文生图」。「按源图片分文件夹」用同一段文字做子目录。提示词和源图都空时不能开始，引擎返回「任务队列为空：请添加提示词，或添加源图片」。扩展实机冒烟同样可以不设 `XBS_EXT_IMAGE`，只设 `XBS_EXT_PROMPT`。

重试按阶段处理：确认发送成功后，等待或保存失败只继续获取原任务结果，不重新上传、标记或发送；已保存的部分图片保留且不重复落盘。发送动作已尝试但无法确认平台是否接受时，停止整批任务并显示错误，请先检查网页再决定是否重新开始。该恢复状态仅在当前批次内有效，不跨软件重启保存。

调度优先分派空闲浏览器，同一个 Chrome 或 Edge 实例内串行。「发送间隔」在同一实例的连续任务之间生效，冷却不会占用其他浏览器的并发名额，最后一项完成后不再等待。停止任务会取消本地执行、重试和间隔等待，并保留已保存结果；平台已接收的远端生成无法由本地停止操作撤回。

### 可选去水印（实验）

在「任务设置 → 更多设置」里勾选「去水印（实验）」，默认关闭。软件先完整保存网页下载的原图，再在本地识别已校准的角落水印，将处理结果另存为 `原文件名_去水印.png`；原图始终保留，队列每张生成图只显示一个最终结果。处理失败或未匹配时记录警告并使用原图，不会为去水印重新上传、发送或生成。

扩展下载不看这个开关。`browserBackend=extension` 的任务，以及 `cmd/xbs-ext-smoke` 实机保存，都在主机侧先按豆包 CDN 规则去掉 `watermark` / `wm=` 查询（失败再用页面原地址），再对豆包和千问调用同一套 `RemoveWatermark`。匹配成功时写下的就是去水印 PNG。千问地址没有这组参数时不会被改写。细节见 [`extension/README.md`](extension/README.md)。

当前适配 2026-10-22 校准的豆包、千问**正方形网页导出图**，包括千问左上角「AI生成」与右下角标记。通过归一化相关匹配固定字形，再按字形蒙版估算背景并补偿邻近细纹理。没有完整背景的真实值，复杂纹理、线条或主体上的水印可能留下痕迹，不能保证无损还原；平台改变样式后可能不再匹配。非方图、16 位高精度图、动画和超出处理大小限制的图片保留原样。

算法使用纯 Go 在本机运行，不额外上传图片，也不需要 Python、OpenCV、模型权重或新的 API Key。GitHub 调研参考了 [LSJ Watermark Remover](https://github.com/RusianHu/lsj-watermark-remover/tree/9a2f5c0f4d64edaad704fdabfdc3264c5a2b999c) 的固定模板思路，以及 [remove-ai-watermarks](https://github.com/wiltodelta/remove-ai-watermarks/tree/b5021b0f6872b533f009a2cc50af9726f33e2177) 的定位、蒙版、局部修复流程；两者的既有素材与当前网页样式不完全一致。本项目实现与校准模板独立制作，没有引入这两个项目的代码、模板或运行依赖。模板来源见 [`internal/images/watermarks/README.md`](internal/images/watermarks/README.md)。

## 验证码求解后端

- `free`：纯 Go 边缘特征 + 余弦相似度（拖拽模式目标匹配 / 拼图模式全排列搜索），完全离线。
- `custom`：任意 OpenAI 兼容视觉模型（默认 SiliconFlow + Qwen3-VL），九宫格返回序号、滑块返回缺口比例。
- `ikunocr`：接码平台（提交 type=1026 → 轮询）。

free 解不了的（描述类九宫格、滑块）自动落到 custom 兜底（配置了 key 时）。

### 迭代记录（测试驱动修复）

1. **桥结果未解析**：页面 `xbsCall` 曾拿到 JSON 字符串而非对象，验证码结果被一律判失败 → `base.js` 按需二次解析。
2. **JS 返回值双重编码**：`Evaluate` 对 `JSON.stringify()` 的返回给出"字符串的 JSON"，直接 Unmarshal 必失败 → 新增 `cdp.ParseJSValue` 统一双解（修复上传诊断/等待结果/抓字节/页面状态四处，"等结果永久超时"根因）。
3. **源图回声**：上传源图的预览图会被结果 hook 误收集 → 引擎预计算源图 SHA256，命中即跳过。
4. **放置区误判**：`[id*="target"]` 会命中九宫格上方的提示参考图（IMG）→ 目标区匹配排除 IMG/PICTURE 且必须在格子下方；新增按文本特征（拖/放置/放入/到这里）+ 位置的兜底扫描，替代固定 `+50px` 落点。
5. **浏览器调度与进度**：起始序号改为在队列分配时按各平台独立取模；同一浏览器的任务串行执行，不同浏览器保持并发；进度计数与队列发布增加同步保护。
6. **保存失败重试**：目录创建或写入失败时撤销结果哈希占用，恢复输出目录后可正常重试；短 RIFF/WEBP 输入不再触发越界崩溃。
7. **原生界面实测**：限定面板高度并恢复表单滚动，源图与队列采用持久的垂直分区；图片导入在主线程合并去重；文件与目录对话框从后台调用，避免阻塞 UI 动作。
8. **启动与打包**：配置库打开失败时输出明确错误并退出；macOS 打包版使用用户配置目录，手动启动与任务共用 profile 目录；补齐固定 v0.6.2 的 MyGo tool 声明，使 `go tool mygo` 与 `./build.sh` 可直接运行。
9. **工作台布局**：调整平台、提示词和保存设置的顺序，补齐空状态、任务状态与操作禁用；队列在窄窗口下优先显示状态、结果和错误，验证码密钥采用密码输入。
10. **发送与结果识别**：等待异步输入与点击结果，发送失败返回实际错误；上传预览就绪后再标记结果，排除源图预览 URL 的延迟变化，保留真正的新生成图片。
11. **软件内启用 ego lite**：浏览器页切换会立即保存，平台打开按钮与任务引擎共用 ego lite 接入；连接错误在界面与日志中显示，Chrome 实例作为可选方式保留。
12. **真实输入与上传**：提示词使用浏览器可信输入；上传入口使用一次真实鼠标点击，捕获本次文件选择器的节点，避免选错旧控件。确认当前附件就绪后再发送，发送前后共用编辑器语义读值，忽略非编辑占位节点并保留真实正文。上传只触发一次 change，清理附件不会修改富文本编辑器或操作历史消息。
13. **生成候选与落盘**：无效、源图和重复候选不会立即结束任务，继续在等待窗口内取结果；流式图片链接保留签名参数。图片限制解码分配并完整解码后，按实际格式确定扩展名，以独占创建避免并发覆盖；取消会停止保存，后续写盘失败保留已保存的结果记录。结束状态区分成功、失败和未完成。
14. **旧网页升级**：软件检测旧版结果脚本后迁移到同一会话地址的干净页面，保留原页和登录状态，后续复用升级后的页面；千问的旧入口重定向后仍可复用已有页。
15. **跨域图片读取**：页面 fetch 因跨域策略失败时，通过浏览器 CDP 读取图片，保留登录态和完整签名参数；HTTP 403 等服务端错误仍明确返回。Chrome 与 ego lite 的隔离跨域页面已验证，平台实测结果以实际落盘验收为准。
16. **Ego 官方 SDK 下载流程**：上传、填写、点击、按键与文件下载交给官方 Page SDK。网页下载先写入私有临时目录，再复用 Go 校验与防覆盖保存；下载失败保留先前有效结果，损坏文件会报错，取消不会继续提交文件。软件仅回收自己已退役且确认无正文草稿的页面，防止旧测试页占满空间。
17. **网页消息与预览**：按本次提示词的新增用户消息锚定助手回复，适应旧消息重建与虚拟滚动；同一图片容器的原图和缩略表示归为一个图项。豆包二级上传菜单、千问的“上传图片”菜单、客户端推广遮挡、无标准对话框标记的图片编辑器及其“保存”入口均单独处理，下载后关闭预览供下个任务复用。千问通过官方 SDK 键盘导航到唯一图片选项后确认，目标或焦点异常即报错；存在未发送正文时保留草稿并停止上传。
18. **验证码误判与开关修复**：图片编辑器和普通画布不再仅凭 canvas 被当成验证码；识别要求局部专用标识或明确验证指令，未知类型不会默认按九宫格处理。关闭自动求解后只检测并上报阻塞，不再尝试求解、拖拽、刷新或提交；已安装页面也能更新开关。旧验证码监听按脚本版本迁移到同一地址的新文档，保留登录状态。
19. **人工验证与任务恢复提示**：发现需要人工验证时保留当前页面，不迁移或刷新验证码，不自动重试、重传或重发；同一 Ego 空间内任务串行，整批停止后显示独立的“待验证”状态与操作提示，已保存结果保留。交还浏览器的独立超时也保留“待验证”；真正取消任务仍优先停止。重新连接优先使用活跃的同平台页面。
20. **退出保存与日志布局**：正常退出时保存当前设置，已通过未失焦编辑、退出重开和配置库核对；长日志单行展示，完整详情可悬停查看，避免脚本堆栈挤满工作区。
21. **千问生成过渡态**：附件入口通过官方 SDK 聚焦并按下方向键打开菜单，再确认唯一的图片选项。生成卡的 loading 占位图保持等待，回复工具栏图标不再作为结果；只在当前助手正文图片完成加载后尝试网页下载。
22. **千问图片编辑页**：按“回到对话”、图片列表及编辑工具共同识别无 dialog 标记的编辑器，只点击侧栏外唯一的“下载”文字控件。关闭时先发送 Escape，仍未关闭时最多点击一次该编辑器明确的“关闭”按钮，再确认预览消失。
23. **可选本地去水印**：增加默认关闭且随设置保存的开关，原图完整落盘后才匹配已校准字形并另存 PNG；未匹配、处理或另存失败时保留原图并记录警告，不重发生成。覆盖取消、动画、并发防覆盖、文件名过长及真实下载样图；细纹理补偿减轻局部插值的平滑字形痕迹。
24. **按阶段重试与空闲浏览器调度**：参考 [chatgpt2api 的续轮询实现](https://github.com/basketikun/chatgpt2api/blob/dc105e51bd486bd75c8ef4f74be4bc4724bdfc33/services/image_task_service.py#L438-L508)，在现有浏览器任务边界内继续获取结果；发送状态不确定时停止，避免自动重发。修复忙碌浏览器阻塞空闲浏览器、并发绕过发送间隔，以及最后一次失败额外等待的问题。未引入新依赖。
25. **只要提示词**：源图留空时按每条提示词 × 每个平台建任务，ego / Chrome 和扩展都不上传。有源图时仍是图生图顺序循环。文生图结果文件名取提示词第一行。
26. **开跑步骤与图标**：主界面直接选文生图或图生图。文生图只需要提示词；图生图再添加源图。平台、打开网页和开始在同一区域。命名、调度和去水印收进默认折叠的「更多设置」。`resources/icon.png` 供窗口、Dock、Windows 安装器和 Linux 桌面项使用。

## 边界说明

## 发布 0.1.2

桌面端产品版本是 **0.1.2**：`mygo.json` 的 `version`，以及 `cmd/xbs/version.go` 的 `ProductVersion`。`go tool mygo build` 会把这个版本链进安装包。页面桥扩展是 **0.3.6**（`extension/manifest.json` 和 hello 的 `payload.version`）。协议信封仍是 `v: 1`。Go 模块版本由 git 标签决定，不写在 `go.mod`。

相对已发布的 0.1.1：用户界面名改为「tulai」（技术 id 和可执行文件仍是 xbs）；网页方式去掉 ego lite，改为 Chrome 和 Edge；页面桥扩展加上 popup。扩展版本仍是 0.3.6。0.1.0 的安装包里还没有「检查更新」，要先手动装上带这个入口的版本。

`.github/workflows/ci.yml` 在 pull request 和 `main` 上跑短测试、`go tool mygo vet`，并上传 macOS、Windows、Linux 的安装包。合并进 `main` 之后，推送和 `mygo.json` 一致的标签，用 `GITHUB_TOKEN` 创建 GitHub Release。没有配置 Apple 公证或 Windows 代码签名。

```sh
git checkout main
git pull origin main
git tag v0.1.2
git push origin v0.1.2
```

附件名称、校验、各系统安装方式和签名限制见 [`docs/RELEASING.md`](docs/RELEASING.md)。
